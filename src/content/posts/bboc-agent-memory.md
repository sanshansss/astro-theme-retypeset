## 一个让我停下来的句子

读《The Big Blob of Compute Hypothesis》时，有一句话让我停了下来：

> 记忆架构可能成为未来候选，因为它们利用了普遍的稀疏性。

我的第一反应不是「有道理」，而是：「这是十年前的论文？那时候就有人谈 memory 了？」

在我的印象里，memory 是 LLM 出现之后才变成显学的东西——上下文窗口、RAG、向量库、MemGPT、各种 memory framework。十年前的深度学习还在解决 CNN、RNN、LSTM 这些事，怎么会有人认真谈记忆架构？

这个疑问后来变成了整篇阅读的主线。我沿着它问了四个问题，每一个都修正了我一次。

## 第一次修正：memory 不是 LLM 之后才有的

我查了一下时间线，发现自己错得挺彻底：

- 1982，Hopfield 网络，联想记忆；
- 1997，LSTM，名字里就带 memory；
- 2014，Neural Turing Machine，可微外部记忆 + 读写头；
- 2014/2015，Memory Networks、End-to-End MemN2N；
- 2016，Differentiable Neural Computer、MERLIN。

2014–2016 恰恰是 memory-augmented neural network 最热的时候。论文那句话不是在预言十年后的 agent memory，而是在**回应当时的热点**：为什么这一类工作在他框架里算「合法算法」。

我把「术语的流行时间」和「问题的年龄」混了。memory 作为一个问题，比 LLM 老得多；只是 LLM 之后，它换了一个形态重新流行。

那个新形态是什么？我后来用一张表把它分开了：

| 层次 | memory 是什么 | 谁在学 |
|---|---|---|
| 十年前的论文 | 一种架构先验，利用稀疏性 | 梯度 |
| Memory Networks / NTM | 网络内部的可微外部存储 | 梯度 |
| 今天的 agent memory | 模型外部的一圈系统 | 多数是手写规则 |

结论是：**不是同一个东西。是同一个词、同一条思想谱系，但不是同一层对象。** 那时的 memory 是模型的一部分；今天的 agent memory 大部分是模型外面的一圈工程。

## 第二次修正：该做参数化记忆吗？

既然论文把「参数」定义为持久存储，我自然想到：那是不是应该把记忆塞进权重？

我一开始的答案是「是」。后来发现，这个答案只对了一半，而且错的那一半很关键。

按论文第 2 条，存储分成两种：训练中学到的通用信息（权重）、执行中学到的任务实例信息（激活）。所以：

- 通用、可复用的结构 → 权重；
- 任务实例、用户特定、时效性事实 → 外部存储，因为它们本来就是「临时存储」那一类。

更准确的说法是：**参数化的是策略，外部化的是内容。**

也就是说，「参数化记忆」不是把每条事实变成权重，而是让「写什么、何时读、何时忘」这个决策函数被训练出来。内容仍然可以是外部的数据库。

这里还有一个论文自己没处理的问题：它写于 LLM 之前，没有建模**权重更新的成本不对称**和**灾难性遗忘**。改一条事实要重训，写一行 KV 是 O(1)——这是外部记忆今天大行其道的真实原因，也是 BBOC 框架的盲点。

所以我的结论是：纯参数化在 BBOC 的理想世界里成立，在工程现实里不成立；纯外挂（今天的 agent memory）在工程现实里成立，在 BBOC 的判准下大半不合格。能同时满足两边的，是「可学习的记忆策略 + 外部的记忆内容」。

## 第三次修正：「进梯度」到底指什么？

我接着问了一个更细的问题：所谓「策略必须进梯度」，是指策略本身可学习，还是指记忆内容可学习？

我一开始把这两个混在一起了。后来拆成三样东西才清楚：

| 成分 | 是什么 | 该不该进梯度 |
|---|---|---|
| 内容 | 存下来的具体记录 | 一般不进 |
| 表示 | 内容怎么编码 / 压缩 / 索引 | 可以进 |
| 策略 | 何时写、写什么、何时读、何时忘 | 必须进 |

「进梯度」不是说把每条记忆变成权重，而是说**控制记忆读写的那个函数是被训练出来的**，不是 if-else 写死的。

这个区分让我对今天的 agent memory 有了一个很直接的判据：**关掉梯度，系统还能不能按同样方式工作？** 能，说明策略是手写的；不能，说明策略是学出来的。

用这个判据去看，大多数 agent memory 框架——MemGPT、Mem0、LangChain memory——都过不了。它们的记忆在计算图外，读写策略是开发者写的。它们不是没有价值，但那是系统工程的价值，不是算法创新的价值。

## 第四次修正：BBOC 到底在说什么？

读到这里，我一度得出一个很顺的结论：BBOC 认可梯度训练，认为不需要再改进学习算法，核心是 infra 而不是算法。

这个结论听起来很顺，但基本是错的。

第一，它认可的是「深度学习整套栈作为基底」，并且反对「缺少关键学习算法」论——即认为存在某个尚未发现的算法（赫布学习、反传替代品）。它不是说梯度下降是真理，而是说另起炉灶大概率失败。

第二，它没有说「不需要改进算法」。它说的是改进只在一个很窄的空间里：

| 类别 | 解决什么 |
|---|---|
| 利用对称性 / 结构 | 减少需要学的比特数 |
| 改善数值条件化 | 数值稳定、优化走得动 |
| 让计算图更顺滑 | 算力自由流动、不被强行切块 |

所以不是「不改算法」，是**改的对象是计算的组织方式，不是学习规则**。

第三，也不是「infra vs 算法」。infra 只是算力的使能条件。BBOC 的核心是「一大堆低结构算力 + 用环境、经验分布、训练目标这几个高层旋钮塑形」。环境设计和训练目标既不是算法也不是 infra，而恰恰是它认为最重要的东西。它自己还留了一句：「这并不意味着扩大当前精确算法的规模就能带来 AGI。」

## 三类筛子，和一张 2×2

把这三类拿去筛现在的 agent memory 工作，我发现它们基本能落进四个格子：

|  | 记忆在计算图内 | 记忆在图外 |
|---|---|---|
| 策略是学的 | Memory Layers、Titans / TTT、NTM / DNC、RETRO | Memory-R1、MemAgent、Mem-alpha |
| 策略是写的 | Transformer-XL、Compressive Transformer | MemGPT / Letta、Mem0、Zep、RAG、LangChain |

我的判断是：

- 左上：BBOC 真正认可的形态——结构 + 计算流都过；
- 右上：最现实的折中——策略进了梯度，但内容还在图外；
- 左下：手写架构，但至少在图内；
- 右下：脚手架——大多数「agent memory」产品在这里。

这个格子对我最大的用处，不是给谁打分，而是让我知道自己站在哪。如果我做的是右下角，我就老实承认这是系统工程；如果我想做算法创新，我就得往上走一格——要么把策略学出来，要么把记忆挪进图里。

## 我保留的怀疑

我对这套框架不是全盘接受。

它最大的问题，是**后验解释力太强、可证伪性太弱**。任何算法成功都可以被解释成「它其实只是在利用对称性」；任何失败都可以说成「结构太僵化」。这既是它的吸引力，也是它的危险。

还有几个我不太满意的地方：

- 核心证据是「Google 那个实验」，但作者说具体替换成了哪种 ML 模型「不能透露」——无法核验的单一来源。
- 雪花隐喻偷换了一层：雪花的形态由物理定律完全决定，智能体的行为由训练目标部分决定。
- 它一边说算法不重要，一边说「利用对称性」是最有效的创新——而对称性本身就是最典型的手工结构先验。作者的化解是「模型最终也会自己发现对称性」，但这个化解只在他的框架内成立。

所以我的用法是：**把它当筛选器，不当证据。**

## 最后

这篇文章没有告诉我「某个技术怎么做」。它给我的是一套判断研究方向的直觉，以及三个可以反复问自己的问题：

1. 这个工作利用了哪条真实存在的结构？访问策略是学的还是写的？
2. 它改善的是数值条件，还是只是把内容搬来搬去？
3. 记忆在计算图内，还是图外的一个控制循环？关掉 prompt，梯度能穿过读写吗？

我一开始以为 memory 是 LLM 之后才有的问题。读完才发现，问题一直存在，只是每一代人用自己的工具重新问一遍。而 BBOC 给我的提醒是：**别急着发明新算法，先看清楚你让计算怎么流动。**
